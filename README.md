# PipeTwin — прогноз остаточной толщины стенки

Решение кейса Nedra Digital PipeTwin. Для каждого 10-метрового сегмента двух труб прогнозируется
минимальная остаточная толщина стенки, мм. Итоговый файл — [`result.csv`](result.csv).

| Кейс | Труба | Дата прогноза | Сегментов | Сценарий |
|---|---|---|---:|---|
| 1 | 1250022871 | 01.12.2023 | 525 | Между обследованиями: прошлые ВТД есть |
| 2 | 1250009583 | 01.07.2022 | 1 475 | От ввода: ВТД этой трубы нет |

Формат файла: `id,segment_id,thickness_pred`, 2 000 строк, ключи `segment_id` от 0 до n−1 для
каждой трубы, точка как десятичный разделитель.

## Запуск

Python 3.11 и новее (проверено на 3.13).

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pipetwin --data-dir /path/to/raw-csv
```

Папка `--data-dir` содержит шесть исходных CSV организаторов: `pot_south.csv`,
`altitudes_south.csv`, `vtd_south_train.csv`, `uzt_south.csv`, `repcorr_south.csv`,
`tech_mode_for_embedings_with_length_with_temperatures_ids16.csv`.

Команда пересобирает `result.csv` из исходных данных примерно за 10 секунд. Промежуточные таблицы
пишутся в `outputs/` (не хранятся в Git, путь меняется через `--work-dir`). Результат
детерминирован: SHA-256 `7b97151da88b4b3b691798f0c0d35076ad34434839f505ef5f5e62c480056b5c`.
Версии пакетов закреплены: pandas 3 несовместим с кодом очистки.

Тесты (с переменной `PIPETWIN_DATA` дополнительно проверяется, что конвейер из исходных CSV
даёт тот же `result.csv` байт в байт):

```bash
PIPETWIN_DATA=/path/to/raw-csv .venv/bin/python -m unittest discover -s tests -v
```

## Решение

**Метрика** — квадрат корреляции Пирсона внутри одной трубы. Она оценивает порядок сегментов
(какие тоньше), а не уровень в миллиметрах.

### Кейс 1 — 1250022871

Главный источник ошибки — координаты: одометр нового прогона прибора смещается относительно
прошлого на несколько метров, и 10-метровые сегменты двух ВТД не совпадают. Поэтому прогноз
строится из последнего ВТД (06.07.2022) тремя способами:

1. **Строгий.** Ожидаемый минимум 10-метрового окна по всем сдвигам в пределах неопределённости
   одометра, усреднённый с минимумом трёх соседних сегментов. Ширина неопределённости и скорость
   потери стенки оценены по прошлой паре ВТД 2018 → 2022. Поправка по двум прошлым ВТД: ранний
   прогон совмещается с последним по сварным швам, рост сопоставленных дефектов продлевается до
   даты прогноза.
2. **Узкое окно.** То же с половинной шириной неопределённости, без поправки по двум ВТД.
3. **С привязкой.** Прибор 01.12.2023 прошёл всю магистраль, и в выгрузке есть его отчёты по
   соседним участкам 1250009490 и 1250011604. По совпавшим швам 2022 и 2023 годов одометр 2023 года
   ушёл на +1,8 м у начала трубы и на +7,5 м у конца. Последний ВТД сдвигается по линейной
   интерполяции. Прогноз — 0,85 × ожидаемый минимум в окне ±2 м + 0,15 × базовый прогноз без
   привязки, минус потеря стенки за 1,4 года.

**Итог** — смесь трёх стандартизованных прогнозов с весами 2,632 / −2,872 / 1,24, переведённая в
миллиметры уровнем и разбросом прогноза с привязкой (`pipetwin/solution.py`, `BLEND`). Веса дают
максимум корреляции с фактом, рассчитанный по формуле r = wᵀr / √(wᵀΣw): r каждого прогноза взят из
оценок организаторов, Σ — корреляции прогнозов между собой.

| Прогноз | r² | MAE, мм | MAPE | Источник |
|---|---:|---:|---:|---|
| Строгий | 0,238 | 0,42 | — | оценка организаторов |
| Узкое окно | 0,182 | 0,412 | 7,9 % | оценка организаторов |
| С привязкой | 0,238 | 0,38 | 7,5 % | оценка организаторов |
| **Итоговая смесь** (`result.csv`) | **0,33** | — | — | оценка организаторов; расчёт до отправки 0,340 |

### Кейс 2 — 1250009583

Своих ВТД у трубы нет, а режим в выгрузке задан одной строкой на трубу в сутки, поэтому сегменты
одной трубы он не различает. Из пространственных признаков сильнее всего связана с утонением высота
трассы, сглаженная по окну 2 км (201 сегмент): выше трасса — тоньше стенка.

- **Порядок сегментов** — по сглаженной высоте (`pipetwin/case2_elevation.py`).
- **Уровень и разброс в мм** — от эталонной модели (`pipetwin/case2_reference.py`). Модель выбрана
  среди 14 вариантов по пространственным блокам первых обследований до 01.07.2022; выбрана
  двухэтапная модель на признаках ПАОТ (вероятность зарегистрированного дефекта × его глубина).

Историческая проверка: средний r² 0,031 на шести длинных обследованных участках выгрузки
(от 300 сегментов), знак связи одинаковый на всех шести. У выбранной двухэтапной модели на тех
участках, где её можно проверить, — 0,0095.
Ширину окна выбирали по всем обследованным участкам, включая обследования 2023 года, которые
позже целевой даты.

## Какие данные использует прогноз

| Часть | Данные |
|---|---|
| Очистка, сетка, разметка | Все шесть CSV; правила из разъяснений организаторов (ниже) |
| Кейс 1, строгий и узкое окно | Только записи строго до 01.12.2023 (`History.before`) |
| Кейс 1, привязка | Дополнительно положения сварных швов соседних участков в прогоне 01.12.2023 — по разъяснению организаторов. Толщина самой 1250022871 на эту дату не читается |
| Кейс 1, веса смеси | Оценки организаторов (r²) трёх прогнозов этой трубы — калибровка по обратной связи |
| Кейс 2, эталонная модель | Первые обследования других участков до 01.07.2022 |
| Кейс 2, ширина окна высоты | Выбрана по всем обследованным участкам, включая 2023 год |

## Очистка данных

- ВТД MAIN-1 от 28.12.2014 раньше ввода труб (16.03.2016): 13 511 строк исключены.
- Все 67 замеров УЗТ исключены: они толще номинала.
- Глубина дефекта в ВТД 2018 года записана долей, в остальных — процентом; приведена к процентам.
- Исключены записи за паспортными границами участка и без положительной остаточной толщины.
- Итог по ВТД: 48 291 → 34 231 строка.
- Сегмент обследованного участка без зарегистрированного дефекта получает паспортный номинал.

## Структура

```
pipetwin/
  solution.py         запуск: исходные CSV -> result.csv, проверка формата, смесь кейса 1
  data.py             очистка, 10-метровая сетка, разметка
  forecast.py         кейс 1 от прошлых ВТД, сборка прогнозов обоих кейсов
  anchoring.py        привязка одометра по швам соседних участков
  case2_reference.py  эталонная модель кейса 2: признаки, пространственные блоки, выбор
  case2_elevation.py  порядок сегментов кейса 2 по сглаженной высоте трассы
tests/test_solution.py
result.csv
```
