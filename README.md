# PipeTwin — прогноз остаточной толщины стенки

Решение кейса Nedra Digital PipeTwin. Прогнозируем **минимальную остаточную толщину стенки в миллиметрах** для каждого 10-метрового сегмента двух труб. Готовый файл сдачи — [`result.csv`](result.csv).

[Отдельные результаты по каждому кейсу](https://drive.google.com/drive/folders/1fTQuUPRxwrjoiixTS09-Uf9BoSbnstBs?usp=share_link)

| Кейс | Труба | Дата прогноза | Сегментов | Результат |
|---|---|---|---:|---|
| 1. После предыдущего ВТД | `1250022871` | 01.12.2023 | 525 | **Pearson r² = 0,33** по оценке организаторов |
| 2. До первого ВТД | `1250009583` | 01.07.2022 | 1 475 | **Pearson r² = 0,046** по оценке организаторов |

Файл [`result.csv`](result.csv) содержит 2 000 строк и три колонки `id,segment_id,thickness_pred`, десятичный разделитель — точка. Номер сегмента считается от начала каждой трубы: `segment_id = floor(расстояние_м / 10)`, от 0 до n − 1.

## Как запустить

Нужен Python 3.11–3.13 (проверено на 3.13). Версии зависимостей закреплены в [`requirements.txt`](requirements.txt). Для обучаемых моделей фиксируем seed 42. Ожидаемый результат можно проверить по SHA-256.

**Данные.** Исходные CSV выдают организаторы, в репозиторий они не входят. Положите в одну папку шесть файлов:

- `pot_south.csv`
- `altitudes_south.csv`
- `vtd_south_train.csv`
- `uzt_south.csv`
- `repcorr_south.csv`
- `tech_mode_for_embedings_with_length_with_temperatures_ids16.csv`

**Linux, macOS, WSL:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pipetwin --data-dir /path/to/raw-csv --out outputs/result.csv
```

**Windows (PowerShell):**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pipetwin --data-dir "C:\path\to\raw-csv" --out outputs\result.csv
```

**Google Colab** (загрузите шесть CSV в папку `data`):

```python
!git clone https://github.com/kekshrine/pipetwin-full-house.git
%cd pipetwin-full-house
!pip install -q -r requirements.txt
!python -m pipetwin --data-dir /content/data --out outputs/result.csv
```

Промежуточные таблицы сохраняются в `outputs/`, другой каталог задаёт `--work-dir`. После запуска там появятся [`forecast_components.csv` (код экспорта)](pipetwin/solution.py#L116) с прогнозами компонентов до смешивания и [`run.json` (код экспорта)](pipetwin/solution.py#L117-L119) с параметрами запуска, числом строк и SHA-256.

### Проверка

```bash
PIPETWIN_DATA=/path/to/raw-csv .venv/bin/python -m unittest discover -s tests -v
```

Тесты в [`tests/test_solution.py`](tests/test_solution.py) проверяют формат файла, отказ на испорченных файлах, свойства смеси и отсечку по дате прогноза. С переменной `PIPETWIN_DATA` дополнительно пересобирается `result.csv` из исходных CSV и сравнивается с [файлом в репозитории](result.csv).

Проверка в PowerShell:

```powershell
$env:PIPETWIN_DATA = "C:\path\to\raw-csv"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Get-FileHash -Algorithm SHA256 outputs\result.csv
```

Контрольная сумма сгенерированного `outputs/result.csv` должна совпасть с суммой [файла сдачи](result.csv) с переносами строк LF (Linux — `sha256sum`, macOS — `shasum -a 256`, Windows — `Get-FileHash`):

```text
7b97151da88b4b3b691798f0c0d35076ad34434839f505ef5f5e62c480056b5c
```

## Веб-интерфейс

Локальная страница показывает прогноз вдоль каждой трубы, подсвечивает 10 % самых тонких сегментов и выгружает `result.csv`.

```bash
.venv/bin/python -m pipetwin.web --data-dir /path/to/raw-csv --open
```

На Windows можно открыть [`start-pipetwin.cmd`](start-pipetwin.cmd) из проводника: он запустит сервис и откроет его в браузере. В этом случае исходные CSV должны лежать в папке `raw_data` рядом с папкой репозитория. Оставьте окно запуска открытым, пока работаете со страницей.

При старте сервис пересобирает прогноз из исходных CSV тем же конвейером, что и `python -m pipetwin`. В форме выберите трубу, режим («После ВТД» для `1250022871`, «От ввода» для `1250009583`) и дату прогноза (01.12.2023 или 01.07.2022). Код — [`web.py`](pipetwin/web.py), страница — [`web/index.html`](pipetwin/web/index.html).

## Как устроен конвейер

| Этап | Что делает код | Где посмотреть |
|---|---|---|
| **1. Очистка** | Проверяет идентификаторы, даты, координаты и единицы измерения. Строит 10-метровую сетку по паспортной длине и привязывает к ней профиль высот. | [Очистка в `data.py`](pipetwin/data.py#L621) |
| **2. Разметка по ВТД** | Для каждого обследования собирает минимальную толщину внутри сегмента и сохраняет, откуда взято значение. | [Разметка в `data.py`](pipetwin/data.py#L805) |
| **3. Модель шкалы кейса 2** | Обучает двухэтапную модель на первых обследованиях других участков и выбирает лучшую по пространственным блокам. | [`case2_reference.py`](pipetwin/case2_reference.py) |
| **4. Кейс 1** | Строит три прогноза из истории ВТД и объединяет их в итоговую смесь. | [Прогноз](pipetwin/forecast.py), [привязка](pipetwin/anchoring.py), [сборка](pipetwin/solution.py#L77) |
| **5. Кейс 2** | Задаёт порядок сегментов по сглаженной высоте трассы и переводит его в миллиметры шкалой из этапа 3. | [`case2_elevation.py`](pipetwin/case2_elevation.py) |
| **6. Экспорт** | Проверяет колонки, ключи, отсутствие дублей и корректность чисел, сохраняет [`result.csv`](result.csv). | [Проверка](pipetwin/solution.py#L35), [экспорт](pipetwin/solution.py#L105) |

### Допущения при очистке

- **Паспорт задаёт границы трубы.** Записи ВТД за паспортной длиной исключаем.
- **Обследование раньше ввода — ошибка.** ВТД от 28.12.2014 относится к трубам, введённым 16.03.2016: 13 511 записей исключены.
- **Единицы глубины зависят от года ВТД.** В отчёте 2018 года глубина записана долей, в остальных — процентом. Приводим к процентам и сверяем с отношением остаточной толщины к исходной стенке.
- **УЗТ исключаем.** Все 67 замеров толще паспортной стенки. По разъяснению организаторов этот источник в модель не входит.
- **Нужна положительная остаточная толщина.** Записи без неё (324) исключаем.
- **Целевая величина — минимум по сегменту.** Из нескольких допустимых записей берём наименьшую. Если сегмент обследован и дефектов в нём нет, ставим паспортный номинал по правилу организаторов.

После очистки остаётся 34 231 запись ВТД из 48 291.

## Кейс 1. Прогноз после ВТД

Главный источник ошибки — координаты. Одометр нового прогона прибора расходится со старым на несколько метров, поэтому дефект у границы попадает в соседний сегмент. Сначала оцениваем, **куда попадут старые дефекты по шкале нового обследования**, затем вычитаем потерю стенки. Её скорость, 0,149 мм/год, оценена по переходу между ВТД 2018 и 2022 годов. Горизонт прогноза — 1,4 года от ВТД 06.07.2022.

| Компонент | Как получаем прогноз |
|---|---|
| **Строгий** | По ВТД 2022 года сдвигаем 10-метровое окно в пределах неопределённости одометра и усредняем полученные минимумы. Смешиваем результат со средним минимумов трёх соседних сегментов. Дополнительно учитываем рост сопоставленных дефектов по двум прошлым ВТД. |
| **Узкое окно** | Уменьшаем ширину диапазона сдвигов вдвое и убираем поправку по двум ВТД. |
| **С привязкой по стыкам** | Прибор 01.12.2023 прошёл и соседние участки. По совпавшим сварным швам получаем сдвиг его одометра: **+1,8 м у начала** целевой трубы и **+7,5 м у конца**. Интерполируем сдвиг вдоль трубы и считаем ожидаемый минимум в окне ±2 м. В прогнозе 85 % — расчёт с привязкой, 15 % — расчёт без неё. |

Итоговая модель v9 получила **Pearson r² = 0,33** по оценке организаторов.

Код расчёта — [`forecast.py`](pipetwin/forecast.py), [`anchoring.py`](pipetwin/anchoring.py) и [`solution.py`](pipetwin/solution.py).

## Кейс 2. Прогноз до первого ВТД

По целевой трубе нет истории ВТД. Технологический режим задан одной строкой на весь участок за сутки, поэтому соседние 10-метровые сегменты он не различает. Различает их **профиль трассы**.

1. **Порядок сегментов.** Сглаживаем высоту трассы по 201 сегменту, это около 2 км. Чем выше сглаженный профиль, тем меньше прогнозируемая толщина.
2. **Шкала в миллиметрах.** Две модели CatBoost оценивают вероятность зарегистрированной потери металла и её величину. Из их совместного прогноза берём среднее и разброс толщины. Модель выбрана среди 14 вариантов по пространственным блокам первых обследований до 01.07.2022.

На шести длинных исторических участках выгрузки средний r² сглаженной высоты — **0,031**, знак связи совпал на всех шести. Организаторы оценили прогноз для `1250009583` в **r² = 0,046**.

Код расчёта — [`case2_elevation.py`](pipetwin/case2_elevation.py) и [`case2_reference.py`](pipetwin/case2_reference.py).
